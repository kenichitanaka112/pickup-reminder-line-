Schedule

ワークフロー YAML のイメージ

ポイント

  • GitHub 公式：on.schedule に timezone（IANA）を付けられる。
  • 日本は夏時間なしのため Asia/Tokyo と cron の組み合わせが分かりやすい。
  • スケジュール実行は公式どおり遅延しうる（厳密な時刻要件は別途検討）。
on:
  workflow_dispatch:
  schedule:
    - cron: '0 19 13 * *'   # 毎月13日 19:00
      timezone: 'Asia/Tokyo'

Policy

運用依頼の反映（4 点）

1. 失敗時の通知チャンネル
第一優先は通常と同じ LINE グループ（pickup-reminder.yml の失敗ステップで send-local.mjs を再実行）。第二候補は SOUGEI_PREP_FAILURE_WEBHOOK_URL（Discord / Slack Incoming など 1 POST）。さらに必要なら同パターンで Webhook を増やす。
2. 訪問済み → よく行く店
sync-state.json の visitedVenuesLog を build-message.mjs が第1通に取り込み、1 行 1 店＋ [new] で付箋相当。ブラウザの一覧を実際に更新するのは workflow-frame の同期（localStorage）。
3. 前回のフリーメモ（第2通）
freeNotes を sync に置くと previous-memo.txt より優先して第2通「前回のフリーメモ」になる。入力欄を空にする処理はブラウザ側。LINE はコピペ用の別バブルで同時送信。
4. AI サポート
要約・抽出・整形は将来 LLM をオプション段で挿入（README の方針）。現状はテンプレ＋ sync のルールベース。
